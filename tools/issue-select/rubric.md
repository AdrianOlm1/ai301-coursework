# Rubric: is this a good first issue?

All dates and "within N days" are measured back from the capture date on the bundle (eval mode) or from today (live mode).

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| maintainer-alive | Repo facts, "last 5 default-branch commits" (date and author of each) | At least 1 of the 5 commits is dated within 180 days of the capture date AND is authored by a human (not a `[bot]` account), or is a bot "Merge pull request" of a human's PR. Fail if every commit is older than 180 days or is a bot-only automated update (dependency bumps, leaderboard updates). | required |
| repo-in-use | Repo facts: the `archived:` flag, "last push to any branch", "latest release" | `archived: no` AND (last push within 90 days OR latest release within 365 days). Fail if archived, or if both the push and the release are older than those limits, or there is no release and the last push is older than 90 days. | required |
| not-claimed | Repo facts "this issue: assignees / linked PRs"; the Comments section | ALL of: (a) assignees is `none`; (b) no linked PR is `open`, and no comment mentions an open PR for it; (c) no comment in the 30 days before the capture date says someone is working on it, will take it, or asks to be assigned, unless a later comment shows they dropped it or a maintainer released it. Closed or merged linked PRs alone do not fail this check. Claim comments older than 30 days with no PR and no assignee do not fail it. | required |
| scope-bounded | Issue body and Comments section | The issue asks for ONE bounded change a newcomer can finish in a single PR. Fail if ANY of: it lists several independent deliverables meant to be split into separate PRs or tracked as separate sub-issues (an umbrella/tracking/megaissue); it is a support or usage question; a maintainer says it needs core-internals or architecture work; the thread shows the design is still being debated with no maintainer decision; the issue is auto-generated by a bot with no maintainer triage. A numbered list of possible CAUSES or implementation approaches for ONE underlying bug is not a checklist of separate deliverables and does NOT fail this check, even when phrased as "additional suggestions." A short body or a missing reproduction does NOT fail this check. | required |
| ai-policy | Repo facts "contribution policy" line | Fail ONLY if the policy states an outright ban ("we do not accept AI-generated code or contributions") with no allowance for assistive or disclosed AI use. Pass if the policy is silent, or sets conditions (disclosure, personal understanding and testing, human review), or says AI-generated PRs without human review are closed. | required |
| maintainer-responsive | Repo facts, "maintainer first-response sample" | At least 2 of the 5 sampled issues show a first maintainer reply within 30 days. Samples that say "no maintainer comment in thread" and were opened within 7 days of the capture date are ignored, not counted against. | preferred |
| labelled-friendly | Issue labels line | The issue carries `good first issue`, `help wanted`, or `easy`. | preferred |

## Verdict rule

Accept if every `required` check is `pass`. Reject if any `required` check is `fail`. `unclear` on a required check counts as `fail`. `preferred` checks never change the verdict; they only rank accepted issues.
